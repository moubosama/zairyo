## ⑥ エンジン定数の物件横断チェック（棚卸しレポート）

```bash
node scripts/check-engine-constants.mjs
```

- 何をする: エンジンのハードコード定数が「2物件一致」か「物件依存」かを
  アルファ・別府の2物件のXLS実測値と突合して一覧化する。
  さらに従来パス（展開図なし）の実績レンジ・クランプが別府9タイプで頭打ちになるかも出す
- **合否判定はしない**（レポート・exit 0固定）。「どの定数がまだ危険か」の棚卸し用
- **判定ラベルはn=2の弱い証拠**（2026-07-24是正）: 両XLSは同一テンプレートの使い回しで、
  テンプレート値は物件ごとに上書きされている（X9=別府0・X73=1.45→1.5・X81=1.4→1.45が実証）。
  よって「物件不変」ではなく**「2物件一致（テンプレート既定値の可能性）」**と表現し、3物件目で崩れうる前提で扱う
- 現状: 2物件一致11 / 物件依存4 / 要確認2。
  物件依存のうち下地高・遮音壁ルールはoverride対応済み、
  **際根太規格・天井PBのﾊﾟｳﾀﾞｰ加算4枚は未対応（ハードコードのまま）**
- **一部界壁3枚/一部界壁耐水1枚/収納面5枚は面積換算していない固定枚数**（materialCalculator.js:845/856/880）
  なので差は「—」（旧版が1.5/1.45と書いてA-4解決済みと誤認させていたのを是正）。
  実測置換されるEV/防露壁面PBだけは buildupCalculator.js:1236 が1.4で割っており **XLS X62=1.5 に対し-6.7%**（既知A-4を可視化）
- **木製巾木H=40/60は物件依存ではない**（両物件H=60主体・アルファ玄関ブロックのみH=40=8.5%）。
  集計表46行のラベル「H=40」と拾いブロック実態H=60主体の**表記食い違い**として別枠報告（要けいとさん確認）
- **クランプは「展開図あり＝無効」ではない**（是正）: 天井PB(:817)は実測モードでも常時効く（takeoffが天井を置換しないため。
  別府H/Iで50枚頭打ち）。壁PB等もサニティNG時のフォールバックで効く
- 転記元XLSの陳腐化検知: `_meta`にmd5を記録し、原本が手元にあれば`node:crypto`で再計算して照合、
  出力ヘッダに`source_xls_verified: 2026-07-24`とmd5一致状況を出す（xlsx依存は戻さない）
- このスクリプトはXLSを読まない（backend-nodeは`xlsx`を依存から外しているため）。
  比較値は転記済みの定数表で、各エントリの`source`に原本セルを明記してある

## 期待値の根拠（正解データ）

- **アルファ（Gタイプ）= エンジンの精度検証の正**: プロの拾い出しXLS
  `②(仮称)アルファステイツ新宮町（木及び_建材）R6,09,19.XLS`
  - **①の枚数正解 = 「集計表」シート**（発注数量列÷9戸。係数はX列: 壁1.4/天井1.45/界壁1.5）
  - **②の㎡正解 = 「Ａタイプ」シート**（中身はGタイプ・戸数9の部屋×面の拾い）
- **別府（A〜Iタイプ）= 物件横断の汎用性チェック用**: プロの拾い出しXLS
  `(仮称)別府4丁目プロジェクト（木及び_建材）R7,03,08.XLS`
  - 正解 = 「集計表」シートの**戸当列**（A=C列 / B=E / C=G / D=I / E=K / F=M / G=O / H=Q / I=S）。
    各セルはタイプ別シートP列（部位計）への直接参照で、集計表側の加工は無い
  - **図面の読み取り結果は無い**ので精度evalには使えない（係数・定数の物件依存性の検証専用）
  - 注意: 集計表の**行番号は両物件で同じテンプレートだがラベルは違う**
    （例: 81行 アルファ=遮音壁耐水PB係数1.4 / 別府=天井（耐水ＰＢ）1.45）。
    突合は行番号ではなく**ラベル**で行うこと
- 1.6562（サブロク理論値）は使わない。係数は必ず集計表X列の実値を読む
- 摘要の表記は「やまがみ様【見積明細内訳】.xlsx 木工事シート」と同一
  （例: 名称「壁 石膏ボード」摘要「t-9.5（3'×6'）910×1820mm」）
